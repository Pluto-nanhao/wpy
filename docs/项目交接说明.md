## 一、项目概述

sectorfeature 是基于 Gsim 的行业因子回测框架，将通联数据（equ_fancy_factors）中的原始因子按行业做 Winsorize 和等权聚合，生成行业层面的因子值，并进行回测与收益排序。

本项目参考 **AlphaWangpyDatayes** 的实现方式，将因子范围从原先仅支持 table1 扩展至 **table1-10 共 208 个因子**，并完成因子收益排序与统计输出。

---

## 二、核心改动总结

### 2.1 因子范围扩展（table1 → table1-10）

| 模块 | 改动内容 |
|------|----------|
| `config.py` | 新增 `TABLE_FACTORS` 字典，定义 table1-10 共 208 个因子；新增 `ALPHA_LIST`、`FACTOR_TABLE_LIST` |
| `Dmgr_tlsector_eq.py` | 从 `FACTOR_TABLE_LIST` 读取因子，按 `(table_num, factor_name)` 从 `equ_fancy_factors_table{tid}.{f}` 加载数据 |
| `main.py` | 生成包含 208 个 Alpha 的单一 XML，在 XML 中注册 table2-10 的 Data 模块（`equ_fancy_factors_table1` ~ `equ_fancy_factors_table10`） |

### 2.2 因子收益排序

- 回测结束后对每个 PnL 调用 `simsummary.py` 解析统计指标
- 按 Sharpe 比率降序排序
- 输出至 `workspace_eq/results/factor_ranking.csv`

### 2.3 终端输出改进

- 使用 `subprocess.Popen` 替代 `subprocess.run`，使 Gsim 输出**同时写入日志和终端**
- 新增 `_log()` 函数，所有输出 `flush=True` 确保实时显示
- 增加阶段提示：XML 构建、Gsim 运行、simsummary 进度、Top 25 结果等

### 2.4 simsummary 解析修复

**问题**：simsummary 的 `shrp(IR)` 列格式不固定，导致列错位：
- 正数：`0.30( 0.02)` 有空格 → 13 列
- 负数：`-0.92(-0.06)` 无空格 → 12 列

原先按固定列索引解析，`win_rate` 被误取为 `ddStart` 等日期字段。

**修复**：
- Sharpe：查找含 `(` 的 token 并提取数字
- pnl、ret：固定为 `parts[3]`、`parts[4]`
- %dd、%win：从右往左取 `parts[-5]`、`parts[-4]`，避免受列数变化影响

## 四、运行方式

```bash
cd /home/wangpy/sectorfeature/sectorfeature
python3 main.py
```

**流程**：
1. `init_env()`：初始化 configs、logs、pnls、results 目录
2. `build_xml_all()`：生成 `cfg_all_factors.xml`（208 个 Alpha）
3. `run_gsim()`：调用 Gsim 回测，输出同时写入 `logs/gsim_all.log` 和终端
4. `run_summaries_and_sort()`：对每个 PnL 运行 simsummary，按 Sharpe 排序，输出 `factor_ranking.csv`

**仅重新生成排序表**（不重新跑 Gsim）：
```python
from main import run_summaries_and_sort
run_summaries_and_sort()
```

## 九、table1 市值聚合试验（第一阶段，新增）

为满足“先在 table1 上试验不同市值加权和缺失值处理，再推广到全局因子”的需求，新增了试验版实现。

### 9.1 改动文件

| 文件 | 改动内容 |
|------|----------|
| `dmgr_scripts/Dmgr_tlsector_cap.py` | 改为仅处理 table1 因子（20 个），新增可配置加权方式与市值缺失处理方式 |
| `run_table1_cap_trial.py` | 新增试验入口脚本：无需手改 `config.py`，可通过命令行切换参数并运行单组或全组合实验 |

### 9.2 加权方式与缺失值策略

通过环境变量（由 `run_table1_cap_trial.py` 自动设置）控制：

- `CAP_WEIGHT_MODE`
  - `cap_pct`：按行业内个股市值占比加权
  - `softmax`：对行业内个股市值做 softmax 后加权
- `CAP_NAN_MODE`
  - `drop`：若个股 `cap` 为 NaN，则该股票从行业聚合中剔除
  - `fill_sector_mean`：若个股 `cap` 为 NaN，则用该行业当日有效 `cap` 均值填充；若该行业全缺失，则回退到当日全市场有效 `cap` 均值；若全市场也无有效值则该行业当日跳过
- `CAP_TRANSFORM`
  - `none`：不做市值变换
  - `log1p`：先做 `log(1 + cap)`，再计算行业权重（降低超大市值股票权重集中度）

### 9.3 仅跑 table1 的执行方式

```bash
cd /home/wangpy/sectorfeature/sectorfeature
```

#### 单组试验（示例）

```bash
python3 run_table1_cap_trial.py --weight cap_pct --nan drop
python3 run_table1_cap_trial.py --weight softmax --nan fill_sector_mean
python3 run_table1_cap_trial.py --weight softmax --nan fill_sector_mean --cap-transform log1p
```

#### 全组合试验（2x2）

```bash
python3 run_table1_cap_trial.py --all
```

> `--all` 现为全组合：2（weight）x 2（nan）x 2（cap-transform）= 8 组。

### 9.4 输出目录

每组参数会生成独立工作目录，便于横向比较：

- `workspace_cap_t1_cap_pct_drop/`
- `workspace_cap_t1_cap_pct_fill_sector_mean/`
- `workspace_cap_t1_softmax_drop/`
- `workspace_cap_t1_softmax_fill_sector_mean/`
- `workspace_cap_t1_*_*_none/`
- `workspace_cap_t1_*_*_log1p/`

每组结果排序文件位置：

- `workspace_cap_t1_*/results/factor_ranking.csv`

2. 当前阶段只在 table1 验证聚合策略；待策略确认后，再迁移到 table1-10 全量因子。

## 十、三种聚合方式对比结论（table1，20因子）

对比对象：

1. `cap_pct + drop`  
   路径：`workspace_cap_t1_cap_pct_drop/results/factor_ranking.csv`
2. `softmax + fill_sector_mean`  
   路径：`workspace_cap_t1_softmax_fill_sector_mean/results/factor_ranking.csv`
3. `log1p(cap) -> cap_pct + fill_sector_mean`（先对数再直接加权）  
   路径：`workspace_cap_t1_cap_pct_fill_sector_mean_log1p/results/factor_ranking.csv`

### 10.1 核心统计

| 方案 | 平均Sharpe | 中位Sharpe | Top5均值 | Top10均值 | Sharpe>0 因子数 |
|------|-----------:|-----------:|---------:|----------:|----------------:|
| cap_pct + drop | 0.2415 | 0.1300 | 0.6820 | 0.4500 | 17 |
| softmax + fill_sector_mean | **0.3830** | **0.3700** | **0.6880** | **0.5970** | **19** |
| log1p(cap) -> cap_pct + fill_sector_mean | 0.1840 | 0.1500 | 0.6260 | 0.4400 | 14 |

### 10.2 排名特征

- `cap_pct + drop`：头部由 `t1_CORR_VP` 强驱动（Sharpe=1.01），风格偏少数强因子。
- `softmax + fill_sector_mean`：整体更均衡，`NP/REV` 相关因子群显著抬升，整体分布最优。
- `log1p(cap) -> cap_pct + fill_sector_mean`：更“去大市值集中”，但整体 Sharpe 下滑，尾部负 Sharpe 因子增多。

### 10.3 相对 `cap_pct + drop` 的变化

- `softmax + fill_sector_mean`：平均 Sharpe **+0.1415**，20 因子中 **15 升 5 降**。  
  变化较大因子：`t1_REV_Q_YOY(+0.60)`、`t1_NP_YTD_YOY(+0.52)`、`t1_REV_TTM_QOQ(+0.45)`、`t1_NP_Q_YOY(+0.39)`、`t1_CORR_VP(-0.67)`。
- `log1p(cap) -> cap_pct + fill_sector_mean`：平均 Sharpe **-0.0575**，20 因子中 **4 升 14 降**。  
  变化较大因子：`t1_OCFA(+0.42)`、`t1_TA_ENTROPY(+0.33)`、`t1_RROC_Q(-0.41)`、`t1_SUDE(-0.38)`、`t1_UDSL_DWL(-0.37)`。

### 10.4 当前建议

1. 若目标是“整体表现最优、正Sharpe覆盖更高”，优先 `softmax + fill_sector_mean`。  
2. 若你更看重 `CORR_VP` 这类头部因子稳定性，可保留 `cap_pct + drop` 作为对照基线。  
3. “先对数再直接加权”目前更像风险约束型方案，建议仅作为备选，不建议直接作为全量默认方案。

### 10.5 备注

- `workspace_cap_t1_cap_pct_drop/results/factor_ranking.csv` 首行 `factor_id` 处出现 `_VP` 字符异常（应为 `t1_CORR_VP`），不影响主体比较结论，但建议后续统一清洗输出编码。
